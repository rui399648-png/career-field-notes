# 工具开发：澄清、实现、变更、交接

全部角色、回复和数据均为虚构模拟。45分钟核心：5分钟简报＋15分钟实现初稿＋15分钟反馈复核＋10分钟交接回顾。Python标准库即可；环境准备另计。

## 0–5分钟：先澄清组织者的请求

原始请求：“把CSV报名按先后来分名额，重复的别再录，满了留候补，取消的不占位。给我一份结果。”

先写两个问题，再看回复。例如：取消会撤销前面的行吗？同一邮箱能报不同项目吗？跳过的行是否也要输出？

**组织者回复：**“这是报名快照，`cancelled`只表示本行已取消，不撤销别的行。ID与邮箱都**全局**去重，跨项目也只能一次；确认与候补都占去重位置。取消、无效行不占名额或去重位置。**每行都要返回结果**，保持输入顺序。细节以 `starter.py` 的规则为准。”

在自己的笔记中确认这三点，再手算前四行。不要把页面报名的‘取消按钮’语义套到CSV快照上。

## 5–20分钟：写函数，验收初稿

补 `starter.py` 中两个函数；CSV读写和输出已准备。先跑一个正常例，再验收：

```powershell
python starter.py
python check_tool.py starter.py
```

原验收共8项，包含顺序、去重、取消、无效、容量与输出。记录一次真实运行：`命令｜预期｜实际｜第一项失败｜我准备查哪条规则`。只会一部分也保留代码，不用把失败藏起来。

## 20–35分钟：收到一次容量变更，复核结果

**组织者反馈：**“摄影演示容量改为3；Python项目暂不确认任何人，容量0但有效报名保留候补；剪辑容量1。其他规则不变。请确保从容量文件读取，不能在函数里写死2。”

使用新文件 `workshop-capacity-revised.csv`。项目代码仍是 `mobile-photo`、`python-tools`、`video-edit`；不要改原容量文件。正确程序可能只需换配置，也算落实变更。

```powershell
python check_tool.py starter.py
python starter.py --capacities workshop-capacity-revised.csv --output learner-output-revised
```

先跑旧验收确认规则未退化，再跑新样例确认3/0/1容量生效。核对12行结果保持顺序，摄影最多3人、Python确认0人但有候补、剪辑最多1人。初稿如未完成，可尝试修一处或留下一个失败样例；按需看 `tool-change-reference.md`，注明借助了哪部分。

## 35–45分钟：交给下一个使用者

同事追问：“后面有一行cancelled，会把前面的同邮箱报名删除吗？”根据确认后的快照规则回复一句。交接说明写：

`文件位置与需求版本｜运行命令｜换了哪份容量配置｜验收结果与输出总数｜输入是快照｜未完成/未测/限制｜下一步`

提醒使用者：同一个输出目录的同名CSV会覆盖；原输入不会改写。这个练习没有实时取消、数据库、并发分配或正式上线流程。解释本次结果，避免只说“程序可以运行”。

留最后5分钟记录：澄清规则、写逻辑、追失败、接变更、给别人说明，各自哪里投入、哪里疲劳？得到提示后还想继续哪一环？完成度与兴趣分别记。
