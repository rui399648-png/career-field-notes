# v4 岗位试玩扩展设计

目标：在已发布的七个工作样本上新增三个互补方向，并在复审与验证通过后更新 GitHub 和 Pages。

## 新增方向

| 方向 | 核心动作 | 必须留下的成果 |
| --- | --- | --- |
| 电商运营 | 修改促销、数量与投放方案，核对预算、库存和贡献额；收到经营变化后重算 | V1/V2 参数与计算证据、改动理由、发布条件和未决项 |
| 供应链与物流规划 | 安排六笔模拟配送，核对容量、时间窗与路线；收到道路变化后重新调度 | V1/V2 路线与实际到达时间、约束差异、调度交接 |
| 交互／UX 设计 | 从模拟体验反馈提炼问题，修改可点击的预约原型，复验正常与错误路径 | 问题与假设、V1/V2 原型参数及操作证据、设计交接 |

每项主轮为 5 / 15 / 15 / 10 分钟，含最后 5 分钟体验记录；可选加做另计。先完成初稿，再查看反馈和参考。纯填表不能代替动手；每个方向都有实际响应参数修改的浏览器工作台。

三个新场景独立于旧题，人物、商品、订单、成本、交通与体验反馈均为教学模拟。计算结果或预写反馈不证明真实经营效果、实际配送效果或真实用户可用性。

## 页面与数据

- 使用原生 HTML/CSS/JS 和相对资源路径，离线、无需账号、无第三方依赖。
- 工作台输入和 V1/V2 快照留在页面内存；提供可复制或下载的文本，关闭前需自行保存。
- 结果必须包含本次参数、场景版本和实际计算／操作证据。修改参数后不得将旧输出配成新结果；不合法输入不产生成功结果。
- 参考方案展示一种可解释选择，不提供一键代做或职业评分。
- 新任务追加独立 ID `ecommerce`、`logistics`、`ux`，现有七项字段和语义不改。继续使用记录 schema 2 和 `career-field-notes-v2` 存储键，保护历史归档、已有 false、计时与损坏记录。

## 集成与完善

- 版本标记统一为 v4，任务总数从实际描述数据生成。
- 首页优先展示本轮新增三项，其余七项完整保留；来源日期按任务显示。
- 更新场景说明，明确新题有独立业务背景；公开页面不再要求回到一个不存在的“本聊天”。
- 从实际任务脚本生成文字手册，更新 README、来源映射、使用说明和审查记录。
- 继续保留原报名样品与 Python 起始题中的教学缺陷。

## 验证与发布

1. 各工作台验证正常输入、边界、无效参数、反馈后的真实变化与快照不可变。
2. 独立重算经营和调度参考，核对数据、页面、描述与材料一致。
3. 页面事件集成验证十项路由、旧记录加载、导入导出、新增字段、计时切换和错误保护。
4. 核对所有本地链接和 JS 语法；实看桌面与手机页面。
5. 以已发布提交 `7e5074a4c5762ab4b821f11b35c67287818eb24b` 为固定点，分别做 Standards 与 Spec 审查，修复实际问题后复验。
6. 仅在验证和 review 完成后提交、正常更新 GitHub main。比较远端提交与本地文件树，等待 Pages 部署成功并逐项核验线上资源。

需求依据和真实岗位职责会汇入根目录的「新增岗位与依据」及「岗位参考与任务映射」。行业规模、海外预测与招聘样本分别说明其范围，不能推导成本地热门排行或应聘资格。
